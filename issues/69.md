## Description
Implement structured logging throughout the application using `ILogger<T>` with `LogInformation` method. Since error handling is centralized in middleware that already logs errors, the focus should be on informational logging for tracking application flow, important operations, and business logic execution.

## Tasks
- [ ] Add `ILogger<T>` injection to all controllers and services
- [ ] Implement `LogInformation` calls for key operations (e.g., entity creation, updates, deletions)
- [ ] Add logging for important business logic execution points
- [ ] Log request processing milestones (e.g., "Processing request for...", "Operation completed successfully")
- [ ] Ensure log messages include relevant context (entity IDs, operation types, user identifiers where appropriate)
- [ ] Review and ensure middleware error logging is functioning correctly
- [ ] Remove any redundant error logging in lower-level code (since middleware handles it)

## Acceptance Criteria
- [ ] All controllers and services inject `ILogger<T>` appropriately
- [ ] Key operations throughout the application log informational messages
- [ ] Log messages are clear, concise, and provide useful context
- [ ] No duplicate error logging exists (errors are only logged by middleware)
- [ ] Logging follows consistent patterns across the codebase
- [ ] Application logs can be used to trace request flow and business operations
